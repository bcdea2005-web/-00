# لوحة تحكم Sanity — مطعم مشوي

لوحة تحكم كاملة (Sanity Studio v3) لمشروع `197665fs / production`، تشمل كل أنواع
المحتوى التي يقرأها الموقع (إعدادات الموقع، الأقسام، الأصناف، الإضافات، العروض)
**ومنها حقل «صورة خلفية الواجهة (Landing Page)»** في إعدادات الموقع — الصورة التي
يعرضها الموقع كخلفية كبيرة وفوقها لون أحمر خفيف.

## التشغيل محلياً

```bash
npm install
npx sanity login        # سجّل الدخول بحساب Sanity المالك للمشروع
npm start               # يفتح على http://localhost:3333
```

أضف `http://localhost:3333` إلى قائمة CORS من
[sanity.io/manage](https://www.sanity.io/manage) → المشروع → API → CORS Origins.

## نشرها كلوحة رسمية للمشروع

```bash
npm run deploy
```

> ملاحظة: النشر يجعل هذه الـ Studio هي اللوحة المستضافة للمشروع (بدل الحالية).
> المخطط هنا يحتوي كل الحقول الحالية (العنوان، العنوان الفرعي، القصة، العنوان،
> الهاتف، واتساب، الشريط المتحرك، طرق الدفع، ساعات العمل) **plus** حقل صورة الخلفية،
> فلا تفقد اللوحة الحالية أي شيء.

## صورة خلفية الواجهة

من اللوحة: **إعدادات الموقع → صورة خلفية الواجهة (Landing Page)** → ارفع صورة
واحفظ. الموقع يعرضها فوراً كخلفية كبيرة (cover) وفوقها لون أحمر خفيف.
امسح الحقل واحفظ → يعود شعار المطعم كخلفية افتراضية.

## إعدادات الموقع مستند مفرد (Singleton)

هيكلة اللوحة في `sanity.config.js` تفتح «إعدادات الموقع» دائماً على مستند واحد
بمعرّف ثابت (`siteSettings`) — وهو نفس المستند الذي يقرأه الموقع — فأي تعديل
الخلفية أو أي حقل آخر ينعكس مباشرة على الموقع. كما تُخفي اللوحة أزرار
«تكرار/حذف» لهذا المستند وتمنع إنشاء إعدادات ثانية من قائمة «+».

> **مهم:** كانت المشكلة سابقاً وجود مستندَي `siteSettings` — اللوحة تعدّل أحدهما
> والموقع يقرأ الآخر، فبدت الخلفية وكأنها «لا تتغيّر» والصورة القديمة «عالقة».
> بعد نشر هذه الهيكلة (`npm run deploy`) وتوحيد البيانات مرة واحدة بسكربت
> `sanity-seed/fix-settings.mjs` (انظر `sanity-seed/README.md`) لن يتكرر الأمر.
> يكفي تشغيل أي منهما لحل المشكلة، ومع الاثنين معاً لا يمكن أن تعود.
